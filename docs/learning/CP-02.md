# Study & test guide — CP-02: domain model, state machine, errors, ports

*Budget ~4–6 h. Read §1–§2 with the files open in VS Code, run §3, do §4, answer §5, sign off (§6).*

CP-02 writes the **language of the system**: the types every later checkpoint talks in. No database, no API, no
model — only pure Python. Mistakes here are expensive later, so this guide explains every decision.

## 1. Read the files in this order

## 2. The six decisions and why

**D1 — `Money` allows negative amounts.**
A value object guarantees the *type* (whole rupiah, never float), not business rules. Reconciliation needs
differences: `invoice_total - po_total` may be `Money(-50_000)` ("Rp 50.000 short"). If `Money` refused negatives,
every subtraction would need a workaround. "A total must be > 0" is a validator rule (CP-04), where it produces a
review issue instead of a crash. *Interview line:* "Value objects guarantee representation; validators guarantee
meaning."

**D2 — `FieldMeta` lives next to the document, not inside it.**
`ExtractedDocument`'s JSON schema is sent to the LLM as its output format (structured outputs). If every field were
`{value, confidence, bbox}`, we would be asking the model to *invent* its own confidence — exactly the
uncalibrated number this project exists to replace (blueprint §5.6). So the model outputs plain values, and our
pipeline adds metadata in `ExtractionResult.field_meta`, keyed by paths like `"line_items[0].qty"`.
`is_valid_field_path` rejects typos such as `"totl"`.

**D3 — The state machine is a plain dict, not a library.**
Eleven rows. A dict is readable by anyone, testable for all 100 `(status, event)` pairs, and adds no dependency to
`core` (which must stay pure). Libraries such as `transitions` add callbacks and hidden state that we do not need.
The table is the product's lifecycle: changing it requires an ADR.

**D4 — `ValidationError` → `DomainValidationError`.**
Pydantic already has `ValidationError`, and the same modules use both. `except ValidationError:` would silently
catch the wrong one depending on which import won. Distinct names make the bug impossible. The spec was updated.

**D5 — Two spec inconsistencies fixed: `PageImage` and `Transaction`.**
The old spec had `AmountReader.read(crop: ImageArray)` (a numpy array) and `JobQueue.enqueue_in_tx(conn:
AsyncConnection)` (a psycopg type). Both would break the import-linter rule "core stays pure". Now images cross as
encoded bytes (`PageImage`) and adapters decode them; transactions cross as an opaque `Transaction` protocol that
`core` never looks inside. This is the ports-and-adapters rule in practice: **the inside defines the interface in
its own words; the outside translates**.

**D6 — Repository ports deferred to CP-21/22.**
Their methods depend on the tables (CP-21). Writing them now means guessing, and guesses become rework (YAGNI:
"you aren't gonna need it" — yet). The 8 ports we did write have shapes that are already certain.

**Three more choices you will be asked about:**
- *Every field optional:* a missing invoice number must become a review issue, not a crash that loses the other
  14 fields. Requiredness lives in one table per doc type.
- *Strict money and dates:* `{"amount_idr": 1250000.0}` and `"doc_date": 1696000000` are rejected. A float or a
  timestamp slipping through is how silent wrong values enter a finance system.
- *`qty` as a JSON string:* `"2.5"` is exact; `2.5` as a JSON number may be read as a float by some client.

## 3. Run it on your Mac
```bash
make setup
make gate CP=02
make gates-upto CP=02
uv run python -m cocok_core.schema_export | head -40
uv run pytest -q -m cp02 --hypothesis-show-statistics -k Lifecycle
```
Try the models yourself:
```bash
uv run python
```
```python
from decimal import Decimal
from cocok_core.models import Money, ExtractedDocument, transition, DocumentStatus, Event

Money(10_000).times(Decimal("2.5"), "half_up")
ExtractedDocument.model_validate_json('{"doc_type": "nota", "vendor_name": "  "}')
transition(DocumentStatus.FAILED, Event.RETRY, retry_count=3)
```

## 4. Break it on purpose (undo each with `git checkout -- <file>`)

| # | Do this | Expected |
|---|---|---|
| 1 | In `status.py` delete the row `(_S.FAILED, Event.RETRY): _S.QUEUED` | `make gate CP=02` fails at "tests (cp02)" with 8 failures: `test_every_pair_matches_the_oracle[FAILED-RETRY]`, `test_allowed_events_agrees_with_oracle[FAILED]` and the six retry tests |
| 2 | In `status.py` change `retry_count >= MAX_RETRIES` to `retry_count > MAX_RETRIES` (off-by-one) | Only `test_retry_refused_at_limit[3]` fails. The Hypothesis state machine usually does **not** find it in 100 examples (it needs ~16 events in a precise order). Lesson: random testing complements boundary tests; it does not replace them |
| 3 | In `money.py` change `type(self.amount_idr) is not int` to `not isinstance(self.amount_idr, int)` | `test_rejects_anything_but_int[True]` fails — `bool` is a subclass of `int` |
| 4 | In `document.py` add a field `currency: OptText = None` to `ExtractedDocument` | Gate fails at "tests (cp02)": `test_committed_snapshot_is_up_to_date`. `uv run python -m cocok_core.schema_export --check schemas/extracted_document.schema.json` also says "out of date". Then run the same command with `--write` and look at `git diff schemas/` — this is how a schema change is reviewed. Undo both files afterwards |
| 5 | In `document.py` change `IsoDate = Annotated[date, Strict()]` to `IsoDate = date` | Three `test_rejects_bad_values[...date_type]` cases fail. The scary one is `1696118400`. Try `ExtractedDocument.model_validate({"doc_type": "nota", "doc_date": 1696118400})`: without `Strict()` this midnight Unix timestamp is silently **accepted** as `2023-10-01` — the bug `Strict()` prevents |
| 6 | In `tests/test_ports.py` change `FakeStorage.get` to return `str` instead of `bytes` | Gate fails at "fakes satisfy ports (mypy)": mypy says `FakeStorage` is not a `Storage` |

## 5. Explain-back questions (answer in `docs/progress/CP-02.md`, in your own words)
1. Why is money an `int` of rupiah, and why are negative amounts allowed?
2. Why is every field except `doc_type` optional? Where does "required" live instead, and what happens to a
   missing required field later?
3. Why is `FieldMeta` not inside `ExtractedDocument`?
4. Why are ports `Protocol`s, and why do they take `PageImage` and `Transaction` instead of a numpy array and a
   psycopg connection?
5. The status test has two layers: the exhaustive 100-pair test and the Hypothesis state machine. What does each
   catch that the other might miss? Why is the oracle copied by hand instead of imported?
6. What does `model_validate(..., strict=False)` do to these models, and why is it dangerous?
