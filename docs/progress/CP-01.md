## Explain-back answers (Arka)
*(First draft written by Claude at Arka's request; Arka rewrites them in his own words after studying.)*

1. **What does a uv workspace give us compared with five separate projects?**
   One `uv.lock` and one `.venv` for all five packages, so they always use the same library versions. Local packages
   are linked automatically (`cocok-api` imports `cocok-core` from the folder next to it, edits are visible
   immediately). One command (`uv sync --all-packages`) installs everything, and each package still declares only its
   own dependencies, so the API image will not carry ML libraries.

2. **Why does `uv.lock` matter, and why do the hooks call `uv run --frozen`?**
   `uv.lock` pins the exact version of every library, including indirect ones, for Mac, CI and server — so "works on
   my machine" also works in CI. `--frozen` means "use the lockfile exactly, do not re-resolve": the hook checks the
   code with the same ruff/mypy versions as CI instead of silently upgrading tools.

3. **Name the four import-linter contracts and what each protects.**
   (a) *core is independent* — business logic never depends on DB/LLM/API code, so it stays testable offline.
   (b) *api and worker never import ml* — training/eval code (torch etc.) never enters the production app.
   (c) *core stays pure* — no I/O or heavy libraries (httpx, sqlalchemy, numpy, torch…) inside core.
   (d) *retired dependencies stay retired* — redis, arq, passlib, jose cannot come back by accident (ADR-0004, 0008).
   My test 1b proved (d) works: one `import redis` broke it.

4. **Why are GitHub Actions pinned to commit SHAs instead of tags like `@v7`?**
   A tag can be moved to different code by whoever controls the action's repo; in March 2026 attackers moved 75 tags
   of `trivy-action` to code that stole CI secrets. A full commit SHA always points to the exact code we reviewed.
   Dependabot proposes SHA updates, so pinning does not freeze us forever (ADR-0011).

5. **Why is the gate split into named `step`s instead of one big command?**
   When something fails, the `✘` line names the exact rule that broke (e.g. "lint", "python pins"), so I know where to
   look without reading a long log. It also makes each check runnable on its own for debugging (CHECKPOINTS §0.5).
