## Decisions made in CP-02 (Arka approved: "use the best decisions, explain them")
| # | Decision | Why (short) |
|---|---|---|
| D1 | `Money` allows negatives | Differences (invoice − PO) are needed; "positive total" is a validator rule |
| D2 | `FieldMeta` outside `ExtractedDocument` (`ExtractionResult.field_meta`) | The schema goes to the LLM; it must not invent confidences |
| D3 | State machine = plain dict | 11 rows, exhaustively testable, no dependency in `core` |
| D4 | `ValidationError` → `DomainValidationError` | Avoid clashing with `pydantic.ValidationError` |
| D5 | Ports take `PageImage` and `Transaction` | `core` may not import numpy/psycopg (import-linter) |
| D6 | Repository ports moved to CP-21/22 | Their shape depends on the DB schema (YAGNI) |

## Bugs found while building (AI)
1. **Blank-to-None validator in the wrong place** → `"  "` raised "Input should be a valid string". Root cause:
   the converter ran inside the `str` branch of `str | None`. Fix: wrap the whole `Optional` (`OptText`).
   Test: `test_blank_text_becomes_none`.
2. **`model_validate(..., strict=False)` silently disables `Strict()`** → `{"amount_idr": 5.0}` accepted. Found
   because a test passed that flag. Fix: never pass it; test `test_strict_false_would_disable_the_protection`
   documents the trap.
3. **Docstrings leaked into the JSON schema** (`Args:`, doctests) → would be sent to the LLM. Fix: short model
   docstrings, `json_schema_extra` for `Money`; test `test_schema_has_no_long_docstrings`.
4. **ruff formats Python blocks inside Markdown** → new docs failed `make lint`. Fix: `ruff format` the docs.
